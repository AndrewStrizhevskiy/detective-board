# ADR-0003: MCP servers and SDK

- Status: Proposed (design); SDK pin is based on desk research, not on a run.
- Date: 2026-10-22
- Deciders: tech-lead, mcp-engineer
- Provisional parts: SDK error/timeout surface and tool schema derivation are unverified; evidence-notes server is optional; fetch server is optional.

## Context

The project requires MCP tools in the agent. Timeline and alibi reasoning is not a retrieval problem: it needs deterministic interval logic over dated events with source anchors, which an 8B model does unreliably. Also required: one off-the-shelf MCP server integrated with an allowlist. SDK facts (db-research.md section 5): `mcp` 2.3.0 (2026-10-02, MIT, Python >=3.10); v2 renamed `FastMCP` to `MCPServer`; most online examples target v1; migration doc advises keeping a `<2` bound until migrated.

## Options

1. Own server `timeline-alibi` (stdio) plus an off-the-shelf filesystem (or fetch) server. Optional own `evidence-notes`.
2. Implement the timeline logic as plain Python functions inside the agent (no MCP): simpler, but does not satisfy the MCP requirement and loses process isolation.
3. SDK line: `mcp` v1 (`<2`, FastMCP, many examples) vs `mcp` v2 (`>=2.3,<3`, `MCPServer`, current).

## Decision

- Build `timeline-alibi` as an own stdio server with tools `build_timeline`, `check_alibi`, `find_overlaps` (+ `resolve_entity` TBD); contracts in `docs/mcp-contracts.md`. It reads the index read-only and never calls an LLM.
- Integrate one off-the-shelf server (filesystem preferred, fetch optional and off by default) with a double allowlist: restricted at spawn, and gated in our client wrapper (tool names and resolved paths). Details in `docs/mcp-contracts.md` section 7.
- `evidence-notes` only if time remains after `timeline-alibi`.
- SDK: `mcp>=2.3,<3` in the range, exact version in `uv.lock`; use `MCPServer` and `Client(StdioServerParameters(...))`; do not copy v1 snippets. Imports and error handling are checked against the current SDK docs before the first line of server code.
- Tool errors never become invented answers: a failed call yields a trace event and, if needed, a refusal.

## Consequences

- Deterministic, testable alibi/timeline logic outside the LLM; contracts can be tested with `Client` in-process/stdio without Ollama.
- Depends on a high-quality `time_norm` post-processor (data-schema.md 3.1); if time normalisation is poor, tools return `unknown`/`insufficient_evidence` more often. Measured by eval.
- Two moving parts to maintain (SDK 2.x churn, off-the-shelf server versions, which must be pinned; their package names/CLIs are unverified).
- If the v2 SDK proves unstable in Phase 1, fall back to `mcp<2` with the `FastMCP` API; that would amend this ADR.
