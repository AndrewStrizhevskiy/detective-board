# Руководство по работе на сервере (пошагово, с командами для терминала)

Русская версия [SERVER_RUNBOOK.md](SERVER_RUNBOOK.md). Читайте сверху вниз и выполняйте команды по порядку.
Каждый шаг заканчивается блоком **«Ожидаем»** (как выглядит успех) и **«Если не так»**.

Сеанс: **вторник 27.10 с 14:30**; запасной слот: среда 28.10, 12:00–18:00; заморозка проекта: среда 18:00.
Сервер доступен до воскресенья вечером, но после заморозки демо-сборку менять нельзя.

Условные обозначения: `[НОУТ]` — команда на ноутбуке; `[СЕРВЕР]` — команда на сервере; `<...>` — подставьте своё.

---

## Часть A. Что это такое и что сказать, если спросят

Это **пакетный инференс** готовой открытой модели (qwen3:4b; при необходимости qwen3:8b) по 596 фрагментам текста
20 рассказов о Шерлоке Холмсе. **Обучения и дообучения нет.** Сервер предвычисляет данные (кеш извлечения и граф
знаний), а сам агент потом работает офлайн на ноутбуке. Организаторы разрешили предвычисление на другом железе; на
сцене об этом нужно сказать.

Сервер (со слов техподдержки): i7-12700K, 96 ГБ ОЗУ, RTX 4070 (12 ГБ), NVMe 1 ТБ, сейчас ALT Linux, интернет открыт
(гигабит), доступ только очно, сервер «полностью наш». Это общий кафедральный компьютер:
**никаких учётных данных GitHub, токенов и SSH-ключей на нём не оставлять.**

## Часть B. Подготовка на ноутбуке (до выхода из дома, 10 минут)

### B1. Проверить архив

```bash
# [НОУТ]
ls -la ~/server-bundle/detective-board.tar.gz
sha256sum ~/server-bundle/detective-board.tar.gz
```

Ожидаем: размер около 2,4 МБ и хеш
`e302aa3aa0162eeb9e81c447a619fbd0a53aba5eb94cf5824d71197800b416d0` (коммит `1d631fd`).

Если хеш другой или вы пересобирали архив — пересоберите заново и запишите новый хеш:

```bash
# [НОУТ]
cd ~/code/detective-board && git pull --ff-only && scripts/make_server_archive.sh
```

Скрипт собирает архив из HEAD, пишет в него файл `COMMIT` и проверяет его из чистой копии (около 3 минут).

### B2. Положить файлы на флешку (запасной канал передачи)

```bash
# [НОУТ] вставьте флешку; найдите её:
lsblk -f
# допустим, это /media/$USER/FLASH:
cp ~/server-bundle/detective-board.tar.gz /media/$USER/FLASH/
cp ~/code/detective-board/docs/team/SERVER_GUIDE_RU.md /media/$USER/FLASH/
sync && ls -la /media/$USER/FLASH/
```

### B3. Взять с собой

- ноутбук и зарядку; сетевой кабель/адаптер на всякий случай;
- флешку (архив на ней) и вторую пустую флешку/диск (на 16 ГБ и больше) для результатов;
- телефон: подтвердите слот в Telegram у техподдержки перед приходом;
- это руководство распечатанным или открытым на ноутбуке.

## Часть C. На месте: осмотр сервера (20–30 минут)

### C1. Войти и открыть терминал

Работаете за консолью сервера (прямой доступ). Откройте терминал. Если нужно, договоритесь с админом, под каким
пользователем работать (лучше обычный пользователь, а не root).

### C2. Что за машина

```bash
# [СЕРВЕР]
whoami; hostname
cat /etc/os-release | head -3
uname -r
nproc; free -h
df -h ~
nvidia-smi
```

Запишите в блокнот: ОС, ядро, модель видеокарты и объём видеопамяти, свободное место (**нужно не меньше 20 ГБ**).

Ожидаем: `nvidia-smi` показывает «NVIDIA GeForce RTX 4070», 12 GiB.

Если не так:
- `nvidia-smi: command not found` или «couldn't communicate with the NVIDIA driver» → драйвер не стоит. Дайте себе
  20–30 минут вместе с админом (установка драйвера штатным средством ALT Linux). Не получилось → решение о переустановке на
  Ubuntu 24.04 LTS принимает лид (дорого по времени); запасной план: прогон на CPU сервера (медленно) или только
  приоритетные истории.
- Свободно меньше 20 ГБ → попросите у админа место (`df -h` на других разделах).

### C3. Есть ли интернет и нужные программы

```bash
# [СЕРВЕР]
curl -sI https://ollama.com | head -1
curl -sI https://astral.sh | head -1
command -v tmux git curl tar python3 uv ollama
```

Ожидаем: `HTTP/2 200` (или 301/302) на оба адреса; `tmux`, `curl`, `tar` найдены.

Если не так:
- Нет `tmux`: `sudo apt-get install -y tmux` (ALT Linux использует apt-rpm; если sudo нет — спросите админа или работайте
  в `screen`, если он есть, иначе держите терминал открытым и не закрывайте крышку).
- Нет интернета → нужны файлы моделей и колёса на флешке (раздел 0 в `SERVER_RUNBOOK.md`); сообщите лиду.

### C4. Запустить tmux (всё дальнейшее делайте внутри)

```bash
# [СЕРВЕР]
tmux new -s extract
```

Шпаргалка: отсоединиться — `Ctrl+b`, затем `d`; вернуться — `tmux attach -t extract`; новое окно — `Ctrl+b`, затем
`c`; переключение окон — `Ctrl+b`, затем номер окна; прокрутка — `Ctrl+b`, затем `[` (выход `q`).

## Часть D. Развернуть проект

### D1. Передать архив на сервер

Вариант 1, по сети (с ноутбука, если сервер доступен по SSH из той же сети):

```bash
# [НОУТ]
scp ~/server-bundle/detective-board.tar.gz <USER>@<SERVER_IP>:~/
```

Вариант 2, с флешки:

```bash
# [СЕРВЕР] вставьте флешку
lsblk -f
sudo mkdir -p /mnt/usb && sudo mount /dev/<sdX1> /mnt/usb      # подставьте раздел флешки из lsblk
cp /mnt/usb/detective-board.tar.gz ~/
sudo umount /mnt/usb
```

(Если раздел примонтировался автоматически в `/run/media/...`, просто скопируйте оттуда.)

### D2. Проверить и распаковать

```bash
# [СЕРВЕР]
cd ~
sha256sum detective-board.tar.gz        # сверьте с хешем из B1
mkdir detective-board && tar xzf detective-board.tar.gz -C detective-board
cd detective-board
cat COMMIT                              # должен начинаться с 1d631fd
ls
```

Ожидаем: хеш совпал; в каталоге `scripts/`, `src/`, `data/`, `docs/`, `COMMIT` и т. д.

Если хеш не совпал → не распаковывайте, скопируйте архив заново.

## Часть E. Окружение (bootstrap, 20–40 минут)

### E1. Пробный запуск, ничего не меняет

```bash
# [СЕРВЕР] в каталоге ~/detective-board
scripts/server_bootstrap.sh --check-only
```

Скрипт печатает все проверки и строки `WOULD: ...` (что он собирается сделать). Прочитайте их. Покажите админу
пункты, которые меняют систему (установка Ollama, `sudo systemctl edit ollama`).

### E2. Настоящий запуск

```bash
# [СЕРВЕР]
scripts/server_bootstrap.sh --with-8b
```

Что делает: проверяет GPU и место, ставит `uv` (если нет), ставит Ollama (если нет), задаёт
`OLLAMA_NUM_PARALLEL=4` и `OLLAMA_KEEP_ALIVE=24h` (через systemd, если есть sudo; иначе запускает `ollama serve` вручную),
скачивает модели (`qwen3:4b`, `qwen3:4b-instruct`, `bge-m3`, `qwen3:8b`), `uv sync`, прогоняет тесты, доказывает
использование GPU. **Перед изменениями система просит подтверждение: покажите это админу и отвечайте «да» только если
он не против.** Пишет `data/cache/server/bootstrap.env` и `bootstrap.log`.

Ожидаем: в конце `PASS` и подсказка следующего шага.

Если не так (`FAIL`):
- прочитайте причину в последних строках и в `data/cache/server/bootstrap.log`;
- не запускайте дальнейшие шаги; исправьте причину и запустите скрипт ещё раз (он идемпотентен);
- та же ошибка дважды → остановитесь и напишите лиду (приложите последние 30 строк лога).

### E3. Ручная проверка Ollama и GPU

```bash
# [СЕРВЕР]
ollama --version                  # на ноутбуке 0.35.0; запишите версию
ollama list                       # должны быть qwen3:4b, qwen3:4b-instruct, qwen3:8b, bge-m3
nvidia-smi --query-gpu=name,memory.total --format=csv
```

Сверьте колонку ID в `ollama list` с `docs/team/models.md`. Другой ID означает другую сборку модели: запишите это в
отчёт, смешивание кеша с ноутбука придётся обсудить с лидом.

## Часть F. Проверка воспроизводимости и скорости (10–20 минут)

### F1. Детерминизм и проба параллельности

```bash
# [СЕРВЕР]
scripts/server_run_all.sh --dry-run                       # посмотреть план, ничего не запускается
scripts/server_run_all.sh --phase determinism,probe
```

Что происходит: 3 фрагмента рассказа Boscombe Valley перезапускаются на сервере и сравниваются с выводом ноутбука
(`merge_extract_cache.py verify`); затем проба на 1, 2 и 4 параллельных потока определяет лучшее число потоков.

Ожидаем: отчёт «сколько из 3 совпали байт в байт» (часть несовпадений из-за другого оборудования допустима, если
смысл тот же) и выбранное число потоков, секунды на фрагмент. **Запишите оба числа.**

Если не так:
- все 3 различаются по смыслу → остановитесь и сообщите лиду: кеш с этого сервера нельзя смешивать с кешем ноутбука без
  решения;
- больше 60 с на фрагмент на GPU → CPU-режим или занятая карта: `ollama ps`, `nvidia-smi`.

## Часть G. Сравнение моделей на 12 размеченных фрагментах (30–60 минут)

```bash
# [СЕРВЕР]
scripts/server_run_all.sh --phase gold12
```

Сравнивает qwen3:4b и qwen3:8b на подсказке `extract-2.1` (она остаётся по умолчанию, v2.2 была хуже). Результат — таблица
в `docs/spike/results/gold12-<метка>.md` и в `data/cache/server/report.md`.

**Решение (принимает лид по таблице; если связи нет — берите 4b):** если qwen3:8b заметно лучше по утверждениям и связям
(claims и relations), при этом JSON валиден на 100% и привязка цитат не ниже 0,9, а скорость приемлема, то полный прогон
делается моделью 8b. Иначе остаётся qwen3:4b. **Пока лид не решил — полный прогон не запускайте.** Ключ кеша включает
модель, поэтому все шарды обязаны использовать одну и ту же модель.

Если времени мало: этот шаг можно пропустить (`--skip-gold12`), и тогда берём qwen3:4b.

## Часть H. Полный прогон (часы)

### H1. Запуск

```bash
# [СЕРВЕР] qwen3:4b (по умолчанию)
scripts/server_run_all.sh --phase run,finish
```

Что делает: делит 596 фрагментов на шарды, запускает их параллельно (231 фрагмент с ноутбука уже лежит в кеше и
подхватывается как «затравка»), затем `finish`: слияние кешей, сборка графа `data/graph/graph.sqlite`,
нормализация, отчёт.

Если решили использовать qwen3:8b: сначала `scripts/server_run_all.sh --dry-run` и посмотрите, как задавать модель
(кеш затравки с ноутбука относится к qwen3:4b и для 8b не подойдёт); подробности ручного запуска шардов:
`scripts/extract_shard.sh <k> <N> qwen3:8b` из `SERVER_RUNBOOK.md`, раздел 4.

### H2. Следить за прогрессом

Откройте второе окно tmux (`Ctrl+b`, затем `c`):

```bash
# [СЕРВЕР] второе окно
cd ~/detective-board
scripts/server_progress.sh              # один раз
scripts/server_progress.sh --watch      # обновление каждые 30 секунд (выход Ctrl+c)
```

Показывает: сколько фрагментов готово по каждому шарду, фрагментов в минуту, оценку времени, последние строки логов,
загрузку GPU и список загруженных моделей. Проверяйте каждые 20–30 минут. Общая цифра должна дойти до 596.

### H3. Если что-то упало

- терминал оборвался → `tmux attach -t extract`; шарды в любом случае работают в фоне;
- шард умер → запустите ту же команду `scripts/server_run_all.sh --phase run,finish` ещё раз (возобновляется, готовые
  фрагменты берутся из кеша);
- память GPU закончилась → `scripts/server_bootstrap.sh --parallel 2`, затем повторите запуск;
- хотите собрать граф из неполных данных → `scripts/server_run_all.sh --phase finish --allow-partial` (только если
  времени больше нет).

Ожидаем в конце: сообщение о завершении, список файлов «что забрать», файл `data/cache/server/report.md`.

### H4. Быстрые проверки результата

```bash
# [СЕРВЕР]
uv run python scripts/merge_extract_cache.py count data/cache/extract-cache.sqlite      # ожидаем 596
ls -la data/graph/graph.sqlite
sqlite3 data/graph/graph.sqlite "select count(*) from g_node; select count(*) from g_edge;" 2>/dev/null || echo "sqlite3 нет: пропустите"
sed -n 1,80p data/cache/server/report.md
```

Допишите в последний раздел `report.md` всё необычное: ошибки, перезапуски, замечания админа.

## Часть J. Проход «присутствия» (30–90 минут; только после H)

Проход нужен правилам R1/R3 («человек X в месте P в момент T»). Он запускается **после** сборки графа (берёт из него
списки кандидатов); без `graph.sqlite` скрипт остановится. Качество не измерено, поэтому читайте `eval.json`, прежде
чем верить результату.

### J1. Пробный запуск

```bash
# [СЕРВЕР]
ollama pull qwen3:8b && ollama pull qwen3:4b-instruct
scripts/server_presence.sh --limit 3 --dry-run         # посмотреть команды
scripts/server_presence.sh --limit 3                   # дымовой тест на 3 фрагментах
```

### J2. Рекомендуемый запуск (с проверкой и голосованием)

```bash
# [СЕРВЕР]
scripts/server_presence.sh --verify --samples 3
```

`--verify` добавляет короткую проверку для каждого факта, `--samples 3` запускает проход три раза (seed 42..44,
температура 0,3) и оставляет факты, найденные минимум дважды. Время втрое больше обычного. Прогон возобновляемый.

Дополнительно, если останется время:

```bash
# [СЕРВЕР]
scripts/server_presence.sh --all                       # все истории (демо-фрагменты берутся из кеша)
scripts/server_presence.sh --literal                   # строгий вариант: имя и место буквально в цитате
scripts/server_presence.sh --lenient                   # без новых вызовов модели: сравнение строгий/мягкий
```

### J3. Оценка

Скрипт сам пишет `data/cache/server/presence/eval.json` (в варианте `--verify --samples 3` — `eval-s3-verify.json`). Если
нужно пересчитать вручную:

```bash
# [СЕРВЕР]
uv run python scripts/spike/presence_eval.py data/cache/server/presence/*.jsonl \
    --json data/cache/server/presence/eval.json
```

Прочитайте в отчёте `funnel` (сколько фактов на каждом этапе), `truncated` (если вывод обрезан, поднимите
`--num-predict`; по умолчанию 768) и число оставленных фактов по каждой модели. Запишите в `report.md`: сколько фактов
оставлено, `fact_survival_rate`, найденные находки R1/R3.

## Часть K. Забрать результаты

### K1. Что забрать

Обязательно:
- `data/cache/extract-cache.sqlite` — кеш извлечения;
- `data/graph/graph.sqlite` — граф;
- `data/index/sentences.sqlite` и `data/cache/sentences-emb.sqlite` — индекс предложений;
- `data/cache/server/report.md` и каталог `data/cache/server/logs/`;
- `data/cache/presence-cache-*.sqlite`, `data/graph/presence-*.sqlite`, каталог `data/cache/server/presence/`.

### K2. Подготовить список и контрольные суммы на сервере

```bash
# [СЕРВЕР]
cd ~/detective-board
mkdir -p ~/server-out
cp data/cache/extract-cache.sqlite data/graph/graph.sqlite data/index/sentences.sqlite \
   data/cache/sentences-emb.sqlite data/cache/server/report.md ~/server-out/
cp -r data/cache/server/logs data/cache/server/presence ~/server-out/ 2>/dev/null
cp data/cache/presence-cache-*.sqlite data/graph/presence-*.sqlite ~/server-out/ 2>/dev/null
cd ~/server-out && sha256sum $(find . -type f | sort) > SHA256SUMS && ls -laR | head -50
du -sh ~/server-out
```

### K3a. Вариант 1: по сети

```bash
# [НОУТ]
mkdir -p ~/server-out && cd ~/server-out
scp -r <USER>@<SERVER_IP>:server-out/. .
sha256sum -c SHA256SUMS
```

### K3b. Вариант 2: через флешку

```bash

cp -r ~/server-out /mnt/usb/
sync && sudo umount /mnt/usb
# [НОУТ] после вставки флешки:

cd ~/server-out && sha256sum -c SHA256SUMS
```

Ожидаем: каждая строка `OK`.

### K4. Проверка на ноутбуке (до чистки сервера!)

Бинарные файлы **в git не коммитим.** После успешной проверки напишите в issue

## Часть M. Типичные проблемы (кратко)

| Симптом | Причина | Что делать |
|---|---|---|
| `ollama pull` не работает | нет интернета | модели с флешки (`~/.ollama/models`) |
| Очень медленно (больше 60 с/фрагмент на GPU) | CPU-режим или занятая карта | `ollama ps`, `nvidia-smi`, перезапуск `ollama serve` |
| `merge` отказывается | другая модель, подсказка или опции | сверить с `docs/team/models.md`; `--force` только по решению лида |
| Тесты в bootstrap красные | расхождение окружения | приложить вывод; не продолжать, пока не ясно |
| Терминал оборвался | сеть/окно | `tmux attach -t extract` |
| Нет места | диск | `df -h`, попросить админа |
| Одна и та же ошибка дважды | — | остановиться, записать вывод, написать лиду |

**Нельзя:** менять параметры извлечения (температура 0, seed 42, `num_ctx 4096`, `num_predict 1536`: они входят в ключ
кеша); менять подсказку `extract-2.1` без решения лида; запускать `gh auth login` на общей машине; ставить VPN и
посторонний софт; коммитить бинарные файлы.
