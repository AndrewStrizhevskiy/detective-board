# Руководство по работе на сервере (по-русски)

Это краткая пошаговая версия [SERVER_RUNBOOK.md](SERVER_RUNBOOK.md) (там подробности и ручной вариант).
Сеанс: **вторник 27.10 с 14:30**, запасной слот: среда 28.10, 12:00–18:00. Заморозка проекта: среда 18:00.

## 0. Что это и что сказать, если спросят

Это **пакетный инференс** готовой открытой модели (qwen3:4b, при необходимости qwen3:8b) по 596 фрагментам текста.
Обучения и дообучения нет. Сервер только предвычисляет данные (кеш извлечения и граф); сам агент работает
на ноутбуке. Организаторы разрешили предвычисление на другом железе; на сцене об этом нужно сказать.

Сервер: i7-12700K, 96 ГБ ОЗУ, RTX 4070 (12 ГБ), NVMe 1 ТБ, ОС ALT Linux, интернет открыт, доступ только очно.
Это общий кафедральный компьютер: **никаких учётных данных GitHub и SSH-ключей на нём**.

## 1. Что взять с собой

- ноутбук с зарядкой и кабель Ethernet/адаптер, если нужен;
- архив `~/server-bundle/detective-board.tar.gz` (коммит `1d631fd`, sha256 `e302aa3a…16d0`) и его копия на флешке;
- пустую флешку или внешний диск (на 16 ГБ и больше) для результатов;
- телефон с Telegram (подтвердить слот у техподдержки перед приходом).

Перед выходом проверьте архив:

```bash
sha256sum ~/server-bundle/detective-board.tar.gz
```

Должно совпасть с `e302aa3aa0162eeb9e81c447a619fbd0a53aba5eb94cf5824d71197800b416d0`.

## 2. Первые 20–30 минут: осмотр

```bash
nvidia-smi          # записать модель видеокарты и объём памяти
uname -r; cat /etc/os-release
df -h ~             # нужно не меньше 20 ГБ свободно
curl -sI https://ollama.com | head -1     # есть ли интернет
```

- Драйвер работает и `nvidia-smi` показывает RTX 4070: **ALT Linux оставляем**, ничего не переустанавливаем.
- Драйвера нет и за 20–30 минут он не заводится: обсудите с техподдержкой установку Ubuntu 24.04 LTS (решение принимает
  лид, это дорого по времени).
- Нет интернета: нужны файлы моделей и колёса на флешке (см. раздел 0 в `SERVER_RUNBOOK.md`).

## 3. Развернуть проект

```bash
tmux new -s extract          # всё дальнейшее внутри tmux: обрыв терминала не страшен
# сначала скопируйте detective-board.tar.gz в домашний каталог (scp с ноутбука или с флешки)
mkdir detective-board && tar xzf detective-board.tar.gz -C detective-board && cd detective-board
cat COMMIT                   # коммит должен быть 1d631fd...
```

Отсоединиться от tmux: `Ctrl+b`, затем `d`. Вернуться: `tmux attach -t extract`.

## 4. Подготовка окружения (bootstrap)

Сначала проверка без изменений:

```bash
scripts/server_bootstrap.sh --check-only
```

Затем настоящий запуск (ставит `uv` и Ollama, настраивает параллельность, скачивает модели, гоняет тесты, доказывает
использование GPU):

```bash
scripts/server_bootstrap.sh --with-8b
```

Скрипт спрашивает подтверждение перед системными изменениями (sudo, systemd). **Покажите это техподдержке/админу** и
соглашайтесь только если они не против. Конец вывода: `PASS` и подсказка следующего шага, или `FAIL` с причиной.
При `FAIL` не запускайте дальше; смотрите причину, при необходимости пришлите вывод мне.

## 5. Порядок сеанса (итоговый)

Если времени мало: делайте шаги 1–3 и 6, остальное бонус.

| № | Что | Команда | Время (оценка) |
|---|---|---|---|
| 1 | Окружение | `scripts/server_bootstrap.sh --with-8b` | 20–40 мин |
| 2 | Детерминизм + проба параллельности | `scripts/server_run_all.sh --phase determinism,probe` | 10–20 мин |
| 3 | Сравнение 4B и 8B на 12 размеченных фрагментах | `scripts/server_run_all.sh --phase gold12` | 30–60 мин |
| 4 | Полный прогон + слияние + граф + отчёт | `scripts/server_run_all.sh --phase run,finish` | часы |
| 5 | Индекс предложений | `uv run python -m detective_board.index.sentences` | минуты |
| 6 | Проход «присутствия» с проверкой и голосованием | `scripts/server_presence.sh --verify --samples 3` | 30–90 мин |
| 7 | Оценка прохода присутствия (скрипт шага 6 сам пишет `data/cache/server/presence/eval.json`; при необходимости повторить вручную) | `uv run python scripts/spike/presence_eval.py --help` | минуты |
| 8 | Забрать результаты | см. раздел 7 | 10 мин |

Пояснения:

- **Шаг 3.** Если qwen3:8b заметно лучше по утверждениям и связям и достаточно быстр, полный прогон запускайте с ним:
  `scripts/extract_shard.sh k N qwen3:8b`. Ключ кеша включает модель. Подсказку менять нельзя (остаётся `extract-2.1`).
  Решение по модели принимает лид по таблице отчёта.
- **Шаг 4.** 231 фрагмент уже лежит в кеше ноутбука и подхватывается как «затравка». Если упало, запустите ту же команду
  ещё раз: прогон возобновляемый. Если времени нет: `scripts/server_run_all.sh --skip-gold12`.
- **Шаг 7.** В отчёте смотрите `funnel` и `truncated`; если вывод обрезан, поднимите `--num-predict`.
- Прогресс в любой момент, из второго окна tmux (`Ctrl+b`, `c`): `scripts/server_progress.sh`
  (счётчики по шардам, фрагментов в минуту, оценка времени, последние строки логов).

## 6. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Терминал оборвался | `tmux attach -t extract`; шарды работают в фоне |
| Шард упал | та же команда `server_run_all.sh ...` ещё раз |
| Нехватка памяти GPU | уменьшить параллельность: `server_bootstrap.sh --parallel 2`, затем повторить |
| Результаты детерминизма отличаются от ноутбука | **остановиться** и сообщить лиду: кеш с такого сервера нельзя смешивать без решения |
| Прогон очень медленный | запустить `server_progress.sh`, записать скорость, решить: приоритетные истории или `--allow-partial` |
| Одна и та же ошибка дважды | не зацикливаться, зафиксировать вывод и сообщить |

Нельзя: ставить VPN и прочее ПО сверх `uv` и Ollama; менять параметры извлечения (температура 0, seed 42, `num_ctx 4096`,
`num_predict 1536`): они входят в ключ кеша; запускать на сервере `gh auth login`.

## 7. Что забрать обратно

Файлы (обязательно): `data/cache/extract-cache.sqlite`, `data/graph/graph.sqlite`, `data/index/sentences.sqlite`,
`data/cache/server/report.md` (последний раздел: допишите всё необычное), каталог `data/cache/server/logs/`,
а также `data/cache/presence-cache-*.sqlite`, `data/graph/presence-*.sqlite` и каталог `data/cache/server/presence/` (там `eval.json`).

На ноутбуке:

```bash
mkdir -p ~/server-out && cd ~/server-out
scp USER@SERVER:'detective-board/data/cache/extract-cache.sqlite detective-board/data/graph/graph.sqlite detective-board/data/index/sentences.sqlite detective-board/data/cache/server/report.md' .
scp -r USER@SERVER:detective-board/data/cache/server/logs .
scp USER@SERVER:'detective-board/data/cache/presence-cache-*.sqlite' USER@SERVER:'detective-board/data/graph/presence-*.sqlite' .
scp -r USER@SERVER:detective-board/data/cache/server/presence .
sha256sum * > SHA256SUMS
```

То же самое можно сделать через флешку. Бинарные файлы **не коммитим** в git. Проверьте, что файлы открываются на
ноутбуке (`sqlite3 graph.sqlite 'select count(*) from g_node;'`), и только потом чистите сервер.

После этого напишите в issue #10 «данные с сервера готовы» (это запускает issue #16 с проверкой графа).
