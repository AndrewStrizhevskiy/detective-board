# Доступ к серверу из любой сети через Tailscale (план установки)

Статус: **ПЛАН, на сервере ничего не установлено.** Причина: из других сетей сервер недоступен (VPN университета не
доходит до сети 195.19.35.0/24, разбор в [SERVER_ACCESS_RU.md](SERVER_ACCESS_RU.md), раздел 6). Решение: сервер сам открывает
**исходящее** соединение в сеть Tailscale (WireGuard), входящие порты не открываются, на уровне сети университета ничего менять не надо.
Установка делается один раз **на месте, в сети университета** (оттуда сервер достижим). Команды ниже проверены по
официальной странице пакетов Tailscale для Debian 13 (trixie) на 2026-10-29; версию ОС сервера сверить на месте.

## 0. Решения до установки (лид)

1. **Разрешение администратора кафедры**: на общую машину ставится сетевое ПО, трафик идёт мимо университетского периметра.
   Достаточно одного сообщения администратору, ответ сохранить. В `SERVER_RUNBOOK.md` стояло «ничего кроме `uv` и Ollama»:
   это правило снимается только этим решением.
2. **Чей аккаунт Tailscale**: создаёт лид (вход через GitHub или Google, сам, в браузере). Пароли и ключи в чат не писать.
3. **Кто получает доступ**: список людей, которым нужно подключаться (коллеги по GitHub). Каждый ставит Tailscale на свой компьютер
   и входит в вашу сеть по приглашению, либо вы делитесь только узлом сервера (Tailscale позволяет делиться отдельным устройством).
   Лимиты бесплатного плана на число пользователей проверить в админ-панели заранее.

## 1. Правила доступа (до первого подключения сервера)

В админ-панели Tailscale (раздел Access controls) заменить политику по умолчанию «всем всё» на ограничение: только участники сети
и только порт 22 на сервере. Редактор политики сам проверит синтаксис.

```json
{
  "tagOwners": { "tag:dbserver": ["autogroup:admin"] },
  "acls": [
    { "action": "accept", "src": ["autogroup:member"], "dst": ["tag:dbserver:22"] }
  ]
}
```

Что это даёт: сервер получает метку `tag:dbserver`, к нему можно подключаться только по SSH, сам сервер ни к чьим устройствам
не подключается. Tailscale SSH не включаем: вход остаётся обычным SSH по ключам.

## 2. Ключ для сервера

В админ-панели: Settings, Keys, Generate auth key. Параметры: **не reusable** (одноразовый), срок 1 день, метка `tag:dbserver`.
Ключ вида `tskey-...` показывается один раз, это секрет: вставить его только в терминал сервера, в чат, репозиторий и скриншоты не попадает.
После установки ключ уже недействителен (одноразовый), тем не менее удалить его в админ-панели.

## 3. Установка на сервере (на месте, в сети университета, под `user`)

Проверка версии ОС (ожидается Debian 13, trixie):

```bash
grep -E '^(PRETTY_NAME|VERSION_CODENAME)=' /etc/os-release
```

Если codename не `trixie`, подставить свой в двух адресах ниже (список на https://pkgs.tailscale.com/stable/).

```bash
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkgs.tailscale.com/stable/debian/trixie.noarmor.gpg | sudo tee /usr/share/keyrings/tailscale-archive-keyring.gpg >/dev/null
curl -fsSL https://pkgs.tailscale.com/stable/debian/trixie.tailscale-keyring.list | sudo tee /etc/apt/sources.list.d/tailscale.list
sudo apt-get update && sudo apt-get install tailscale
```

Подключение (ключ ввести вручную; параметры нужны, чтобы не трогать DNS и маршруты общей машины):

```bash
sudo tailscale up --auth-key=tskey-ВАШ-КЛЮЧ --hostname=dbserver --advertise-tags=tag:dbserver --accept-dns=false
```

Проверки:

```bash
tailscale status          # сервер в сети, адрес вида 100.x.y.z
tailscale ip -4           # записать адрес
systemctl is-enabled tailscaled   # enabled: после перезагрузки поднимется сам
```

В админ-панели у сервера отключить истечение ключа устройства (Machines, меню узла, Disable key expiry); у узлов с меткой оно по умолчанию отключено,
проверить. Иначе через 180 дней сервер выпадет из сети.

Параметры SSH на сервере проверить, не меняя: `sudo sshd -T | grep -E 'passwordauthentication|permitrootlogin|pubkeyauthentication'`.
Ожидается `passwordauthentication no`, `pubkeyauthentication yes`. Если `yes` на пароль, написать лиду, не править молча.

## 4. Подключение с вашего ноутбука и с ноутбуков коллег

Установка клиента: https://tailscale.com/download (Linux, macOS, Windows). Затем `sudo tailscale up` (вход в браузере, тот же аккаунт или принятое приглашение).

```bash
tailscale status                                   # виден dbserver
DB_SERVER_HOST=100.x.y.z scripts/server_access_check.sh
ssh user@100.x.y.z
```

В `~/.ssh/config` заменить `HostName 195.19.35.82` на адрес из `tailscale ip -4` (или на имя `dbserver`, если включён MagicDNS).
Ключи SSH остаются теми же (раздел 3 в `SERVER_ACCESS_RU.md`).

На ноутбуке лида работает sing-box в режиме TUN. Маршруты Tailscale имеют более высокий приоритет, чем правила sing-box (они стоят выше в таблице правил),
но это не проверено: после установки смотреть `ip route get 100.x.y.z` (должно быть `dev tailscale0`) и итог `server_access_check.sh`.
Если sing-box перехватывает диапазон 100.64.0.0/10, добавить для него правило «напрямую».

## 5. Откат

На сервере: `sudo tailscale down && sudo apt-get remove --purge tailscale && sudo rm /etc/apt/sources.list.d/tailscale.list /usr/share/keyrings/tailscale-archive-keyring.gpg`,
затем удалить узел в админ-панели. Ничего другого установка на сервере не меняет (мы не трогали `sshd`, файрвол и DNS).

## 6. Безопасность и риски

- Любой участник сети с доступом к узлу видит порт 22 сервера. Ограничение: правила доступа (раздел 1) и ключи SSH (парольный вход выключен).
- Tailscale зависит от внешнего сервиса координации (соединения между устройствами шифруются между ними). Если сервис недоступен, сервер из других сетей снова не виден,
  из университета остаётся прямой вход.
- Кто управляет аккаунтом Tailscale, тот управляет составом сети: хранить доступ у лида, включить двухфакторный вход.
- Это обход периметра университета; без согласия администратора не делать (раздел 0).
- После установки обновить `SERVER_ACCESS_RU.md`: добавить этот способ как основной для работы вне университета, записать реальный результат проверки (проверки «из дома» с Tailscale ещё не было).
