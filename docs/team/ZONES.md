# Roles and zones of ownership

Each role owns a zone of the repository. Edit only files in your zone; for a change elsewhere add a request
line to `docs/backlog.md` (`R-nn | owner | what | priority`) and tell the owner. Cross-zone changes found in
review are rejected. Work packages per person: `docs/team/ASSIGNMENTS.md`.

| Role | Responsibility | Zone and notes |
|---|---|---|
| `agent-engineer` | Orchestrator, query routing, self-check loop, enriched-query format, dialogue memory. | src/detective_board/agent/. Routes: fact->vector, relations/chronology->graph, alibi->MCP, out-of-corpus->refusal. Every claim must carry a quote; unsupported answer -> re-retrieve or refuse. Emit trace events for every step. |
| `backend-engineer` | API layer, trace streaming (SSE/WebSocket), configuration. | src/detective_board/api/, config. Trace stream is the same event schema the UI renders. |
| `code-reviewer` | Independent PR review against checklist; writes no code. | none (read-only). Checklist: correctness, types, tests, error handling, interface adherence, docs, scope. Verdict APPROVE / CHANGES with concrete items. |
| `data-engineer` | Corpus download, cleaning, chunking with source anchors, license checks of texts. | data/, scripts/corpus/, src/detective_board/ingest/. Source: Project Gutenberg, Sherlock Holmes by Conan Doyle, 15-25 stories incl. witness testimony/alibi ones. Verify license and terms of use, record in data/LICENSES.md. Every chunk carries story, section/paragraph anchor and char offsets so quotes can be highlighted. |
| `demo-director` | 7-minute demo script, slides, backup screen recording, rehearsal checklist, jury FAQ. | docs/demo/. Script must rely only on features that work reliably; include fallback for each step. |
| `devops-engineer` | Environment, uv lock, Docker/just, CI (GitHub Actions), one-command build, clean-machine run. | pyproject.toml, uv.lock, justfile, Dockerfile, compose, .github/, pre-commit. ruff, mypy/pyright, pytest. `just run` must work offline after first setup. |
| `eval-engineer` | Golden question set (>=40, with reference answers and sources), metrics, A/B of configurations. | eval/. Metrics: answer faithfulness, citation correctness, out-of-corpus refusal rate, hallucination rate, retrieval recall. Configs: bare LLM / vector only / vector+rerank / hybrid+graph. Output table and chart; one-command run; shortened run for CI. Include unanswerable and adversarial questions. Reference answers must be verified against the actual text. |
| `frontend-engineer` | Investigation board UI: graph, trace panel, quote highlighting. | src/detective_board/web/ (or web/). Cytoscape.js or equivalent, vendored for offline use. Follow the designer's tokens. No CDN at runtime. |
| `graph-engineer` | Graph schema, queries, temporal model, traversals. | src/detective_board/graph/, docs/data-schema.md. Embedded graph DB confirmed by spike (Kuzu candidate). Model: Person, Place, Item, Event(time), Claim(who says what), edges with source anchors. |
| `mcp-engineer` | Own MCP servers (timeline/alibi, optionally evidence-notes) and MCP client; tool contracts; errors and timeouts. | src/detective_board/mcp/. Verify the MCP SDK API in current docs before coding. Also integrate one off-the-shelf server (filesystem or fetch) with path allowlist. Tool contracts documented in docs/mcp-contracts.md. |
| `nlp-extraction-engineer` | Graph extraction schemas, prompts and pipeline on a small model; JSON robustness; entity dedup. | src/detective_board/extract/, prompts/extract/. Strict JSON schema (pydantic), constrained/format-JSON output, retry+repair, validation, entity resolution (aliases like 'Holmes'/'Mr. Sherlock Holmes'), results cached on disk keyed by chunk hash+model+prompt version. Measure extraction precision/recall on a hand-labelled sample. |
| `performance-engineer` | Latency, RAM, model size measurement on the target laptop; 16/8 GB profiles. | scripts/bench/, docs/perf/. Measure on THIS machine (i7-8665U, CPU-only, ~10 GiB free). Report tokens/s, time to first token, RSS peak, with run counts and variance. |
| `product-owner` | Backlog, acceptance criteria (Given/When/Then), priorities, scope control, daily status. | docs/PRD.md, docs/backlog.md, docs/STATUS.md, docs/acceptance/. Cut scope in this order: UI animations, second own MCP server, temporal graph subtleties. Never cut: working demo, citations, honest refusals, quality measurements. |
| `qa-lead` | Test strategy (pyramid), test plan, acceptance verification, regression. | docs/test-plan.md, docs/qa/. Verify acceptance criteria by actually running things; report failures plainly. |
| `retrieval-engineer` | Embeddings, vector index, BM25, reranking, hybrid fusion, k tuning. | src/detective_board/retrieval/. Light local models only. Benchmark on the eval set; report numbers, not impressions. |
| `security-reviewer` | Prompt injection from corpus, MCP tool safety (path sandbox, allowlist), secrets, dependency audit. | docs/security.md, review notes. Read-only on code: report findings with file:line, do not fix other zones. |
| `tech-lead` | Architecture, ADRs, module boundaries, interface review, resolving technical disputes. | docs/architecture/, docs/adr/, interface stubs in src/detective_board/contracts/. Decide with numbers; every significant decision gets an ADR (context, options, decision, consequences). |
| `tech-writer` | README, C4/Mermaid diagrams, ADR index, run guide, metric descriptions. | README.md, docs/ (except zones owned above, edit only by request). Document only what exists and was verified. |
| `test-automation-engineer` | Unit/integration/e2e tests (pytest, Playwright or equivalent), fixtures, LLM mocks for determinism. | tests/. Deterministic suite with mocked LLM; separate 'live' marker for real-model tests. Core coverage >= 80%. |
| `ux-designer` | Demo scenario, information architecture, visual language, accessibility, design tokens. | docs/design/. Node colors per entity type, animation spec, tokens file (CSS variables), 7-minute demo storyline from the user's view. |
