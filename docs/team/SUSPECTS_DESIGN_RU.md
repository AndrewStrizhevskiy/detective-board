# Задача «подозреваемые по уликам до развязки»: разбор и проект (2026-10-28)

Статус: ПРОЕКТ, не реализовано. Не для показа 2026-10-30, кроме этапа 1, если на него останется время.

## 1. Почему система сейчас не решает задачу

1. **Архитектура отвечает одним предложением.** Режим выбора предложения отдаёт одну-две дословные цитаты. Вопрос «кто виновен»
   до развязки не имеет такого предложения по определению: ответ складывается из многих улик в разных местах.
2. **Граф хранит факты, а не улики.** У нас есть люди, места, события, утверждения; нет понятия «улика», «на кого она
   указывает», «кто подозреваемый», «мотив / возможность / средство». Правила R1–R3 проверяют согласованность, а не вину.
3. **Маленькая модель не делает глобальных выводов.** На 4B-модели хорошо работают узкие суждения с ограниченным ответом
   (выбор из списка, enum-схемы, как в presence-2.1), плохо работает «прочитай рассказ и назови убийцу».
4. **Сам Конан Дойл не всегда честен с читателем.** Часть решающих улик появляется только в объяснении Холмса, поэтому даже
   идеальная система не решит все случаи. Это нужно размечать заранее («решаемо по тексту до обрыва: да / частично / нет»).
5. **Измерение было неверным.** В первом варианте теста ключевые слова были фразами из текста развязки («lessen his guilt»,
   «her own life»), поэтому даже полный корпус «не называл» виновного. Исправлено на «назван виновный (имя или псевдоним)» и
   отдельную метрику «обвинён невиновный». Голая модель может знать рассказы наизусть, поэтому без маскировки имён её цифра
   не показывает рассуждение.

## 2. Идея решения: доска дела с методом конкурирующих гипотез

Модель делает только мелкие проверяемые суждения с цитатой, вывод собирают детерминированные правила.

| Этап | Что | Кто делает | Уже есть |
|---|---|---|---|
| A. Подозреваемые | люди рассказа, связанные с жертвой и местом преступления до точки обрыва; плюс «кого подозревает кто» из утверждений | граф (детерминированно) + модель с выбором из списка людей графа | люди графа, связывание имён |
| B. Карточки улик | для каждого фрагмента до обрыва: улика (наблюдение, предмет, след, несоответствие) + цитата + на кого указывает (enum из подозреваемых) + полярность (уличает / оправдывает / нейтрально) + вид (мотив, возможность, средство, алиби) | модель, схема с enum, привязка к цитате, проверка вторым вызовом и голосованием (как presence-2.1 `--verify --samples 3`) | конвейер извлечения, проверка, кеш |
| C. Алиби и время | для каждого подозреваемого: где был по показаниям, конфликты R1, хронология | правила и граф | таблица присутствия, R1, хронология |
| D. Матрица гипотез | подозреваемые × улики: согласуется / противоречит / не относится; ранжирование по МЕНЬШЕМУ числу противоречий (принцип ACH: опровергать, а не подтверждать); исключённые по алиби уходят вниз с причиной | детерминированная функция, без модели | — |
| E. Ответ и доска | рейтинг версий с уликами «за» и «против» (дословные цитаты), список «исключены, потому что…», всегда метка `hypothesis`; запрещено «виновен» | шаблон, как rule-first | доска, шаблоны, проверка честности |

Почему так: граф и правила становятся незаменимыми (сбор десятков улик из разных фрагментов, исключения по алиби, матрица),
модель делает то, что умеет (узкий выбор с цитатой), а каждый шаг виден и проверяем. Это и есть ответ на «это просто поиск».

Предвычисление: карточки улик (этап B) считаются заранее на сервере с GPU (qwen3:8b допустимо, разрешено организаторами),
с позицией в тексте; на ноутбуке остаются только этапы C–E (мгновенно, без модели). Для теста «до развязки» берутся только
карточки до точки обрыва.

## 3. Честное измерение

- **Истина как сущность:** виновный (идентификатор человека и псевдонимы) или категория-поворот (животное, самоубийство,
  несчастный случай); ложно обвинённый (James McCarthy, Simpson, McFarlane, Neligan, Grace Dunbar).
- **Метрики:** виновный на 1-м месте; виновный в первой тройке; средний обратный ранг; «невиновный на 1-м месте» (ложное
  обвинение) с интервалами Уилсона. Для поворотных случаев главная метрика: не обвинить невиновного.
- **Базовые линии:** голая модель; агент-поиск (одна цитата); наивная эвристика «кого больше всех обвиняют в тексте» (повторяет
  ошибку полиции, ожидаемо обвиняет невиновного).
- **Защита от памяти модели:** во всех запросах к модели имена подозреваемых заменяются на нейтральные метки (Mr. A, Mr. B),
  одинаково по всему делу; обратная замена только в ответе.
- **Разметка решаемости:** для каждого дела человек отмечает, есть ли решающая улика до точки обрыва. Главный результат
  считается по решаемым делам; остальные показываются отдельно.
- **Объём:** около 15 дел с человеком-виновным в 20 рассказах; разбиение на dev и test заранее; тест один раз. Мало,
  поэтому только интервалы и парные сравнения, никаких громких процентов.

## 4. Этапы и сроки (ориентир)

| Этап | Содержание | Время | Можно к показу |
|---|---|---|---|
| 0 | исправить тест «до развязки» (имена, «обвинён невиновный», маскировка, решаемость) | часы | да (как честная граница) |
| 1 | «доска подозреваемых» без новых моделей: подозреваемые из графа, таблица присутствия, исключения по R1, кто кого обвиняет; ответ «исключены / не исключены» | 1 день | возможно, если есть время после упаковки |

| 3 | матрица гипотез, ранжирование, доска «версии» в интерфейсе | 1–2 дня | нет |
| 4 | оценка на dev и тесте, сравнение с базовыми линиями, отчёт | 1 день | нет |

## 5. Риски

- Карточки улик с 4B-модели будут шумными (presence-2.1: 7 фактов, 1 оставлен). Без проверки и голосования матрица соберёт мусор.
  Решение: проверка вторым вызовом, порог уверенности, ручная проверка выборки до любых цифр.
- Конан Дойл скрывает улики: потолок решаемости низкий. Это показывать, а не прятать.
- Малый объём: восемь–пятнадцать дел. Любой результат «шум» без интервалов.
- Соблазн «назвать убийцу»: система всегда выдаёт версии с уликами, а не вердикт; формулировки проверяются защитой честности.

## 6. Пересмотр после ночных результатов (2026-10-29)

Что показали измерения:
- **Контроль не проходит:** даже с полным текстом агент назвал виновного в 2 из 16 вопросов; в 10 из 16 нужный фрагмент был найден, но выбрана не та цитата. Значит, первая беда не в «рассуждении до развязки», а в том, что ответ одной цитатой не умеет сказать «это X».
- **Автоматический граф почти пуст для правил:** из 1700 событий только 18 имеют человека, место, день и час, точных 3 (все curated). Доска подозреваемых исключает людей только по ручным фактам.
- **Свободные суждения модели ненадёжны:** судья R3 сказал «противоречит» на 8 из 9 контролей; presence-2.1 оставил 1 факт из 7. Модель срабатывает на общую тему.
- **Память модели не мешает:** голая модель отказалась в 13 из 16 и не знает рассказы; маскировка имён не первоочередна.

Исправленный порядок (каждый шаг меряется до следующего):
1. **Ответ-сущность вместо ответа-цитаты** для вопросов «кто / что виновно»: кандидаты = люди рассказа из графа + «не человек» + NONE, модель выбирает из enum и указывает номера подтверждающих предложений; детерминированная проверка: имя или псевдоним выбранного есть в цитате или в соседнем предложении, иначе отказ. Цель: контроль (полный текст) с 2/16 до большинства. Это же поможет обычным вопросам «кто» в golden (мерить только на dev).
2. **Голоса по фрагментам до обрыва (облегчённые карточки улик):** для каждого фрагмента до точки обрыва один вызов «указывает ли этот фрагмент на кого-то из кандидатов как на сделавшего X: enum людей / NONE + номер предложения», с той же проверкой имени в цитате. Около 240 вызовов на 8 рассказов, на ноутбуке около 20 минут с кешем префикса, сервер не нужен.
3. **Детерминированная сборка (ACH-облегчённый):** по каждому кандидату число независимых подтверждённых фрагментов «за», исключения по алиби с доски, порог воздержания (минимум 2 независимых фрагмента); иначе «улик недостаточно». Порог и правила подбираются на 4 dev-рассказах, проверяются один раз на 4 тестовых.
4. **Главная метрика — не обвинить невиновного:** базовая линия «кого чаще всех обвиняют в тексте» повторяет ошибку полиции (McCarthy, Simpson, McFarlane, Neligan, Grace Dunbar); выигрыш системы — воздержаться или указать на другого с цитатами. Вторая — виновный на первом месте.
5. **Извлечение присутствия и дообучение** (сервер) остаются долгим рычагом для правил R1; на шаги 1–4 они не нужны.

К показу: не встраивать в демо ничего из этого без замеров. Шаги 1–2 можно делать как эксперимент в отдельной ветке параллельно упаковке и репетициям; в демо идёт `rc4`, а результаты (любые) показываются как честная граница.
